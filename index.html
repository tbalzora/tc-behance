Project Overview

A comprehensive tutorial and guide website for Turncloak Card Conspiracy, a social deduction roguelike card game. This single-page site teaches core mechanics, card abilities, and strategy, blending interactive UI components with accessible documentation to help players of all levels learn by doing.

Project Requirements

The project was built to meet a strict set of HTML, CSS, and JavaScript requirements while still feeling like a polished, player-facing game tutorial.

HTML Requirements Structure ▶
  • Single-page HTML file (no multiple pages).
  • Semantic HTML structure with no inline CSS or JavaScript.
  • Real content only, no placeholder text or images.
  • Professional website elements: logo, header, navigation, footer.
  • HTML validation through W3C with zero errors.
CSS Requirements Visual System ▶
  • External stylesheet that validates without errors.
  • Site displays properly at 1280px width.
  • Well-organized, commented, and properly indented CSS.
JavaScript Requirements Interactivity ▶
  • Global "use strict" and clean, modular functions.
  • At least one jQuery widget or plugin beyond a slideshow.
  • Ajax/API: load at least three pieces of dynamic content from an API / mock server.
  • Web Storage: store and retrieve user data using localStorage.
  • jQuery-based slideshow/carousel with at least three images.
  • Scripts loaded with async or defer and no console errors.

What the Requirements Inspired

Instead of treating the assignment as a generic portfolio or business site, I used the requirements as constraints to build something I genuinely wanted: a fully featured tutorial and companion site for Turncloak Card Conspiracy.

  • Theme Switcher: the web storage requirement became a persistent theme system with four game-inspired color schemes: Gambit Heights, Shipwreck Royal, Cedarcrest Chalet, and Cosmic Casino.
  • Interactive Card Showcase: the carousel requirement turned into browsable galleries of all 18 cards with smooth animations.
  • Strategy Tips API: the Ajax requirement evolved into a dynamic strategy tip system that fetches random tips from a Postman mock server, keeping content fresh and replayable.
  • Personalized Experience: web storage powers a username and favorite color system that greets returning players and remembers preferences.

Goals, Purpose & Target Users

Goals

  • Educational: provide comprehensive, easy-to-understand information about game mechanics, card abilities, and strategy.
  • Engagement: create an interactive, visually appealing experience that keeps players exploring.
  • Accessibility: ensure the site is usable by all players, including those with assistive technologies.
  • Performance: deliver fast load times and smooth interactions.
  • Professional Quality: demonstrate mastery of HTML, CSS, and JavaScript best practices.

Purpose

The website serves as the primary tutorial and reference guide for Turncloak Card Conspiracy players. It helps new players learn the game, supports casual players with quick reference, and provides deeper strategy insights for competitive players and game masters. In practice, it operates as a digital companion to the physical card game.

Target Users

  • New Players: discovering the game for the first time and needing clear explanations of rules and mechanics.
  • Casual Players: looking for quick reference to card abilities and basic strategies.
  • Competitive Players: seeking advanced tactics and deeper game knowledge.
  • Game Masters: facilitating sessions and needing fast access to modes, rules, and card details.

Development Process

Phase 1 Discovery & Content Gathering ▶

Research & Planning

  • Analyzed the game’s 18 unique cards (13 good, 5 bad).
  • Documented all four game modes and their configurations.
  • Gathered card images and game assets.
  • Researched similar tutorial websites for structure and interaction patterns.
  • Defined the information architecture and section hierarchy.

Content Strategy

Content was organized into logical sections: Introduction, How to Play, Card Galleries, Strategy Tips, and Feedback. I prioritized information that would be most actionable for players during actual gameplay, and planned interactive patterns (accordions, carousels, and card flips) to support how players learn and revisit information.

Technical Planning

  • Libraries identified: jQuery, jQuery UI, Slick Carousel, Tone.js, Spectrum Color Picker.
  • API integration planned using a Postman Mock Server for strategy tips.
  • Web storage schema defined for username, color, and theme preferences.
  • Layout designed for a 1280px experience with future responsiveness in mind.
Phase 2 Design ▶

Wireframing

  • Created wireframes for a single-page layout with clear sections.
  • Planned navigation flow and anchor-based in-page navigation.
  • Designed card grid layouts and carousel structures.
  • Mapped modal dialogs, accordions, and interactive areas.

Visual Design

I developed four distinct theme color palettes inspired by different game settings:

  • Gambit Heights: purple and gold casino theme.
  • Shipwreck Royal: blue and bronze nautical theme.
  • Cedarcrest Chalet: brown and tan rustic theme.
  • Cosmic Casino: gray and blue futuristic theme.

Card flip animations were designed for interactive exploration, and CSS custom properties were used to ensure each theme felt cohesive and maintainable.

Design Principles

  • Clarity: clean typography, clear headings, and scannable content blocks.
  • Consistency: unified color system and shared components across themes.
  • Feedback: visual indicators for hover, focus, and active states.
  • Accessibility: high contrast, semantic HTML, and appropriate ARIA labels.
Phase 3 Writing the Code ▶

HTML Structure

  • Semantic HTML5 structure with a clear heading hierarchy.
  • Accessibility features including skip links, ARIA labels, and descriptive alt text.
  • Organized sections with IDs for smooth in-page navigation.
  • No inline CSS or JavaScript in the production assignment version.

CSS Styling

  • CSS custom properties used to power theme switching.
  • Responsive grid layouts for card displays at 1280px and beyond.
  • Flip card animations built with CSS transforms and transitions.
  • Hover states and transitions on interactive elements for tactile feedback.
  • Validation through W3C CSS Validator and consistent indentation.

JavaScript Functionality

  • Global "use strict" at the top of the main script file.
  • Modular function structure for maintainability and clarity.
  • jQuery UI Accordion for the “How to Play” section.
  • jQuery UI Dialog for a username modal.
  • Spectrum Color Picker integration for favorite color selection.
  • Slick Carousel for showcasing good and bad cards in separate carousels.
  • Ajax calls to a Postman Mock Server to load strategy tips.
  • localStorage for username, color, and theme preference persistence.
  • Tone.js for interactive card sound effects.
  • Smooth scrolling navigation and feedback form validation.

Key Features Implemented

  • Theme Switcher: dropdown that changes the entire site theme and saves the choice.
  • Username System: modal dialog for setting a username and color, displayed in the header.
  • Card Carousels: auto-playing Slick carousels for the 13 good cards and 5 bad cards.
  • Strategy Tips API: button that fetches and injects random strategy tips from the Postman mock server.
  • Interactive Cards: card flip animations paired with Tone.js sound effects.
  • Accordion: collapsible game instructions for each mode.
  • Feedback Form: validated form with rating inputs for player feedback.

Challenges, Struggles & Learning

Technical Challenges Engineering ▶
  • Carousel Implementation: initially struggled to fit Slick Carousel into the existing card structure. The solution was to create dedicated carousel sections separate from the grid layout.
  • Theme System: designing a comprehensive theme system with CSS custom properties required careful planning so every visual element updated correctly. I solved this by defining all color variables upfront and testing each theme thoroughly.
  • Web Storage Persistence: ensuring preferences correctly persisted across reloads demanded careful use of localStorage, including JSON serialization and robust error handling.
  • API Integration: configuring the Postman Mock Server and gracefully handling API errors led to stronger user-facing error states and fallback messaging.
  • Removing Inline Styles: refactoring early inline styles into reusable utility classes improved maintainability and separation of concerns.
  • Sound Effects Integration: working around browser autoplay policies with Tone.js meant initializing the audio context on user interaction.
Design Challenges UX & Content ▶
  • Information Architecture: organizing a large volume of rules, card details, and strategy content in a single page without overwhelming users. Accordions, carousels, and strong headings helped maintain clarity.
  • Card Display: balancing the need to show all cards with visual appeal led to offering both grid and carousel views to support different browsing styles.
  • Theme Consistency: ensuring all four themes felt cohesive, legible, and on-brand required systematic palette design and repeated testing.
Learning Experiences Growth ▶
  • Deepened understanding of jQuery plugins and widget integration.
  • Learned how to configure and consume Postman Mock Servers for API testing.
  • Gained practical experience building theme systems with CSS custom properties.
  • Improved familiarity with web storage APIs and persistence patterns.
  • Strengthened accessibility practices using ARIA labels and semantic HTML.
